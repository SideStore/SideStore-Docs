# المساهمة في SideStore

شكراً لاهتمامك بالمساهمة في SideStore! يُعد SideStore مشروعاً قائماً على جهود المجتمع، ويتحقق بفضل أشخاص مثلك.

بمساهمتك في هذا المشروع (SideStore)، فإنك توافق على إقرار المطوّر بأحقية المساهمة الموجودة في [CERTIFICATE-OF-ORIGIN.md](https://github.com/SideStore/SideStore/blob/develop/CERTIFICATE-OF-ORIGIN.md). تخضع أي مساهمات في هذا المشروع تتم بعد إضافة إقرار المطوّر بأحقية المساهمة لسياسة ذلك الترخيص.

هناك طرق عديدة للمساهمة في SideStore؛ لذا، حتى وإن لم تكن مطوِّراً، لا تزال هناك طرق أخرى كثيرة يمكنك من خلالها تقديم المساعدة:

- [كتابة الوثائق](https://github.com/SideStore/SideStore-Docs)
- [تقديم تقارير مفصلة عن الأخطاء واقتراح ميزات جديدة](https://github.com/SideStore/SideStore/issues/new/choose)
- المساعدة في تقديم الدعم:
    - [Discord](https://dis.sidestore.io/)
    - [GitHub Discussions](https://github.com/SideStore/SideStore/discussions)

ومع ذلك، سيركز هذا الدليل على الجانب المتعلق بالتطوير. في الوقت الحالي، سنكتفي بتوفير معلومات الإعداد هنا، ولكن يمكنك [الانضمام إلى خادم Discord الخاص بنا](https://discord.gg/sidestore-949183273383395328) إذا احتجت إلى المساعدة بعد الانتهاء من الإعداد.

## المتطلبات

يفترض هذا الدليل أنك:

- تستخدم جهاز Mac
- مثبت برنامج Xcode مسبقاً
- امتلاك معرفة أساسية باستخدام الأوامر في طرفية (Terminal) (معرفة كيفية تشغيل الأوامر والانتقال إلى المجلدات باستخدام الأمر cd).
- امتلاك معرفة أساسية بـ Git (يُعد [GitHub Desktop](https://desktop.github.com/) أداة ممتازة للمبتدئين، إذ يسهّل التعامل مع Git بشكل كبير)
- امتلاك معرفة أساسية بتطوير على Swift/iOS

## الإعداد

1. **قم بعمل نسخة لصفحة SideStore على GitHub**.

2. **استنسخ النسخة عن طريق الأمر التالي في طرفية (Terminal)**:
   ```bash
   git clone https://github.com/<your-github-username>/SideStore.git --recurse
   cd SideStore
   ```
   
   إذا كنت تستخدم GitHub Desktop، فارجع إلى [هذا الدليل](https://docs.github.com/en/desktop/adding-and-cloning-repositories/cloning-and-forking-repositories-from-github-desktop).

3. **انسخ `CodeSigning.xcconfig.sample` الى `CodeSigning.xcconfig`** واملأ القيم.

4. **(لأغراض التطوير فقط)** قم بتغيير قيمة `ALTDeviceID` في ملف Info.plist لتطابق رقم UDID الخاص بجهازك. عادةً ما يقوم برنامج iloader بتضمين رقم الـ UDID الخاص بجهازك تلقائياً في ملف Info.plist الخاص بتطبيق SideStore أثناء عملية التثبيت. أما عند التشغيل عبر Xcode، فسيتعين عليك تحديد هذه القيمة بنفسك، وإلا فلن يتمكن SideStore من إعادة توقيع التطبيقات (أو حتى تثبيتها) للجهاز الصحيح.

5. **وأخيراً، افتح `AltStore.xcworkspace` في Xcode**.

بعد ذلك، قم بإجراء التغييرات واختبارها. ثم قم بحفظ التغييرات عن طريق زر commit ورفعها عن طريق زرpush باستخدام Git، وأنشئ طلب رفع عن طريق زر pull request.

## معلومات عن مكتبة الـ Binary الجاهزة

تستخدم كل من minimuxer وem_proxy ملفات لمكتبات الـ Binary ثابتة ومُعدّة مسبقاً بواسطة GitHub Actions، وذلك لتسريع عمليات البناء والاستغناء عن الحاجة لتثبيت Rust عند العمل على SideStore. سيتم تشغيل `SideStore/fetch-prebuilt.sh` بواسطة Xcode قبل كل عملية بناء، وسيقوم بالتحقق مما إذا كانت ملفات الـ binaries المحملة محدثة مرة كل 6 ساعات. وإذا أردت إجباره على التحقق من وجود ملفات binaries جديدة، قم بتشغيل الأمر `bash ./SideStore/fetch-prebuilt.sh force`.

## البناء باستخدام Xcode

قم بتثبيت cocoapods إذا لزم الأمر باستخدام: `brew install cocoapods`  
الآن، ومن خلال سطر الأوامر في مجلد صفحة SideStore المحملة من GitHub، قم بتنفيذ عملية تثبيت الـ Pods باستخدام الأمر `pod install` لتثبيت تبعيات cocoapod. 
بعد ذلك، يمكنك إجراء عمليات البناء المعتادة داخل Xcode.

## بناء ملف IPA لنشر

قم بتثبيت cocoapods إذا لزم الأمر باستخدام: `brew install cocoapods`  
الآن، ومن خلال سطر الأوامر في مجلد صفحة SideStore المحملة من GitHub، قم بتنفيذ عملية تثبيت الـ Pods باستخدام الأمر `pod install` لتثبيت تبعيات cocoapod. 

يمكنك بعد ذلك استخدام أمر `make build fakesign ipa` في نفس المجلد الخاص بصفحة SideStore المحملة من GitHub.
<br />بشكل افتراضي، يكون إعداد البناء هو `Release`
<br />لإصدارات الـ debug استخدم `export BUILD_CONFIG=Debug;make build fakesign ipa` في نفس المجلد الخاص بصفحة SideStore المحملة من GitHub.
<br />لإصدارات الـ alpha/beta استخدم `export IS_ALPHA=1;` أو `export IS_BETA=1;` قبل استدعاء أمر البناء.  
سيؤدي هذا إلى إنشاء ملف SideStore.ipa.

```sh
أمثلة: 

    # تثبيت cocoapods
    brew install cocoapods
    # pods تنفيذ التثبيت لـ الـ
    pod install

    # alpha إصدار نسخة
    export IS_ALPHA=1;make build fakesign ipa
    # alpha إصدار تجريبي لنسخة
    export IS_ALPHA=1;export BUILD_CONFIG=Debug;make build fakesign ipa

    # beta إصدار نسخة
    export IS_BETA=1;make build fakesign ipa
    # beta إصدار تجريبي لنسخة
    export IS_BETA=1;export BUILD_CONFIG=Debug;make build fakesign ipa

    # stable إصدار نسخة
    make build fakesign ipa
    # stable إصدار تجريبي لنسخة
    export BUILD_CONFIG=Debug;make build fakesign ipa
```

بشكل افتراضي، سيقوم SideStore بعملية البناء باستخدام مُعرِّف الحزمة (bundleIdentifier) ​​الافتراضي `com.SideStore.SideStore`؛ ولكن إذا كنت بحاجة إلى تحديد مُعرِّف حزمة مخصص لعمليات البناء عبر سطر الأوامر، فيمكنك القيام بذلك عن طريق `BUNDLE_ID_SUFFIX`:

```sh
    # stable إصدار نسخة
    export BUNDLE_ID_SUFFIX=XYZ0123456;make build fakesign ipa
    # stable إصدار تجريبي لنسخة
    export BUNDLE_ID_SUFFIX=XYZ0123456;export BUILD_CONFIG=Debug;make build fakesign ipa
```

**ملاحطة**: عند البناء باستخدام Xcode، يتم تعيين `BUNDLE_ID_SUFFIX` افتراضياً بقيمة `DEVELOPMENT_TEAM`.

يمكن تخصيص هذا الأمر من خلال تعيين أو إزالة BUNDLE_ID_SUFFIX في ملف CodeSigning.xcconfig المُنشأ استناداً إلى الملف CodeSigning.xcconfig.sample

:::warning
سيحتوي ملف الـ binary المُنشأ على مسارات تشير إلى مجلد DerivedData الخاص بـ Xcode، وفي حال قمت ببناء minimuxer على جهازك، فسيحتوي أيضاً على مسارات تشير إلى $HOME/.cargo؛ وتتضمن هذه المسارات اسم المستخدم الخاص بك. لذا، إذا كنت ترغب في الحفاظ على خصوصية اسم المستخدم الخاص بك، فقد تفضل استخدام GitHub Actions لبناء ملف IPA بدلاً من ذلك.
:::

## عملية طلب الرفع Pull Request

### قبل الرفع

1. **اتبع معايير البرمجة**: تأكد من أن الكود الخاص بك تتبع [إرشادات التنسيق](./formatting.mdx) لدينا.

2. **اختبر التغييرات التي أجريتها**: 
   - اختبر على إصدارات iOS مختلفة إذا أمكن ذلك
   - تأكد من عدم تعطل الوظائف التي تعمل بالفعل
   - أضف اختبارات للميزات الجديدة إذا أمكن

3. **تحديث الوثائق**: حدِّث الوثائق ذات الصلة إذا كانت التغييرات التي أجريتها تؤثر في الميزات التي يتفاعل معها المستخدمون.

### تقديم طلب الرفع

1. **أنشئ فرعاً (branch) للميزة**:
   ```bash
   git checkout -b feature/اسم-الميزة-الخاص-بك
   ```

2. **أجرِ التعديلات**: التزم بإرشادات البرمجة وأفضل الممارسات.

3. **اعتمد تغييراتك مع إضافة رسالة توضح التعديلات**:
   ```bash
   git add .
   git commit -s -m "اكتب رسالة تصف التغييرات"
   ```
   
   **مهم**: يجب توقيع جميع عمليات الأعتماد (commit) بـ إقرار المطوّر بأحقية المساهمة (DCO). يضيف الخيار `-s` تلقائياً السطر المطلوب لـ `التوقيع من قبل` إلى رسالة الأعتماد الخاصة بك.

4. **ارفع الى نسختك من الصفحة**:
   ```bash
   git push origin feature/اسم-الميزة-الخاص-بك
   ```

5. **إنشاء طلب رفع**: انتقل إلى صفحة SideStore الرئيسية على GitHub وأنشئ طلب رفع (Pull Request) من الفرع (branch) الخاص بك.

:::caution تحذير
نحن **لا** نقبل طلبات الرفع التي يتضح أنها مُنشأة بواسطة الذكاء الاصطناعي أو التي تفتقر إلى الدقة والمنهجية (مثل احتواؤها على تعليقات مفرطة وواضحة، أو كود برمجي يبدو شائع وعاماً، أو ينم عن عدم فهم للمشروع، أو لم يتم إعداده بعناية ليتناسب مع SideStore). يرجى التأكد من أن مساهماتكم أصلية وتعكس فهماً واضحاً لقاعدة الكود وأهداف المشروع.
:::

### إرشادات طلب الرفع

- **عنوان واضح**: استخدم عنواناً وصفياً يلخص التغيير
- **وصف تفصيلي**: اشرح التغييرات التي أجريتها والأسباب
- **ربطها بأي مشكلة مشابهة**: أشر إلى أي مشكلات ذات صلة على GitHub
- **لقطات الشاشة**: أدرج لقطات شاشة لتغييرات واجهة المستخدم
- **ملاحظات الاختبار**: صِف كيف اختبرت التغييرات التي أجريتها

## إقرار المطوّر بأحقية المساهمة (DCO)

تُطالب SideStore جميع المساهمين بالمصادقة على التغييرات البرمجية التي يجرونها باستخدام إقرار المطوّر بأحقية المساهمة (DCO). وتُعد هذه الشهادة بمثابة مدونة قواعد سلوك المساهمين لدينا، كما أنها وسيلة بسيطة للإقرار بأنك كاتب الكود البرمجي الذي تساهم به أو أنك تمتلك الحق في تقديمه.

### ما هو إقرار المطوّر بأحقية المساهمة (DCO)؟

بتوقيعك على جميع عمليات الأعتماد، فإنك تُقر بأن:

- **(أ)** تم إنشاء هذا العمل كلياً أو جزئياً من قِبلك، ولك الحق في تقديمه بموجب رخصة المصادر المفتوحة الموضحة في الملف؛ أو
- **(ب)** تستند هذه المساهمة إلى عمل سابق، وعلى حد علمك، فهو مشمول بترخيص مفتوح المصدر مناسب، ولك الحق بموجب هذا الترخيص في تقديم ذلك العمل مع تعديلات؛ أو  
- **(ج)** قُدِّمت لك المساهمة مباشرةً من قِبَل شخص آخر قام بإجراء المصادقة (أ)، (ب) أو (ج)، ولم تقم أنت بتعديلها.
- **(د)** أنت تدرك وتوافق على أن هذا المشروع والمساهمة فيه هما أمران علنيان، وأنه يتم الاحتفاظ بسجل للمساهمة إلى أجل غير مسمى.

### كيفية كتابة التوقيع

لتوقيع عمليات الأعتماد الخاصة بك، ما عليك سوى إضافة الخيار `-s` عند إجراء الأعتماد.:

```bash
git commit -s -m "رسالة الأعتماد"
```

سيؤدي هذا تلقائياً إلى إضافة سطر `التوقيع من قبل` إلى رسالة الأعتماد الخاصة بك:

```
رسالة الأعتماد خاصتك

Signed-off-by: SternXD <stern@sidestore.io>
```

### ملاحظات هامة

- **يجب توقيع جميع عمليات الأعتماد** - عادةً ما نُفضّل أن تقوم بتوقيع عمليات الأعتماد الخاصة بك.
- **استخدم البريد الإلكتروني الصحيح** - يجب أن يتطابق البريد الإلكتروني مع حسابك على GitHub.
- **إعادة التوقيع بأثر رجعي** - إذا نسيت التوقيع، يمكنك تعديل آخر عملية رفع قمت بها باستخدام `git commit --amend -s`

لمزيد من التفاصيل، يرجى الاطلاع على مستند [إقرار بأحقية المساهمة](https://github.com/SideStore/SideStore/blob/develop/CERTIFICATE-OF-ORIGIN.md).

## عملية مراجعة الكود

1. **مراجعة أولية**: سيقوم أحد المشرفين بمراجعة طلب الرفع الخاص بك في غضون بضعة أيام
2. **التعليق**: معالجة أي تغييرات أو استفسارات مطلوبة
3. **الموافقة النهائية**: بمجرد الموافقة عليه، سيقوم أحد المشرفين بدمج طلب الرفع الخاص بك

## إرشادات للمساهمات الجيدة

- اكتب كوداً نظيفاً وقابلاً للقراءة

- اضف توثيق لطريقة استعمال الـ APIs العامة
